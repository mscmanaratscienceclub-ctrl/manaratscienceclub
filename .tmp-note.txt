74	`kind` fully describes the comparison, and the action layer implements exactly
75	these four — there is no fifth behaviour hiding in a component.
76	
77	| `kind` | SQL | Notes |
78	|--------|-----|-------|
79	| `text` | `ILIKE '%value%'` on one column | Case-insensitive substring |
80	| `select` | case-insensitive equality | `Morning` = `morning` |
81	| `date` | inclusive day range | A `to` date covers that whole day |
82	| `number` | numeric bound | `min` is `>=`, `max` is `<=` |
83	
84	Date bounds convert through `ADMIN_TIME_ZONE` (`Asia/Dhaka`) because the tables
85	store `timestamptz`. A bare date bound would be read as UTC and would split a
86	Dhaka calendar day at 6am local, so "registrations from 14 September" would
87	quietly mean 13 Sep 18:00 → 14 Sep 18:00. See `dayRange` in
88	`src/lib/actions/registrations.ts`.
89	
90	Fields marked `primary: true` render in the always-visible row; the rest sit
91	behind **More filters**, which opens itself whenever a hidden filter is active so
92	a chip is never the only evidence of a filter that is narrowing the list.

124	## Report columns
125	
126	**This is the section `filters.ts` refers to.** `AdminReportColumn.id` is a plain
127	string on purpose: the query layer builds report rows as
128	`Record<string, string>`, keyed by these ids. **The ids below and the object
129	literals in `getAdminReportRows` (`src/lib/actions/registrations.ts`) must stay
130	in step** — TypeScript cannot check a `Record<string, string>` against a config
131	list, so a mismatch shows up as a blank column on paper, not as a compile error.
132	
133	| Source | Column ids, in order |
134	|--------|---------------------|
135	| `ambassador` | `type`, `name`, `class`, `school`, `phone`, `email`, `gender`, `firstTime`, `facebook`, `instagram`, `submitted` |
136	| `volunteer` | `name`, `classSection`, `roll`, `shift`, `studentCode`, `personalPhone`, `parentsPhone`, `submitted` |
137	| `stemfest` | `name`, `class`, `school`, `segments`, `transactionId`, `paymentNumber`, `payment`, `submitted` |
138	| `sms` | `receivedAt`, `sender`, `transactionId`, `amount`, `senderNumber`, `status`, `message` |
139	
140	Formatting is done server-side and in a fixed timezone, because a printout is the
141	one artefact nobody can scroll to double-check:
142	
143	- dates → `reportDate` (`en-GB`, `Asia/Dhaka`)
144	- empty strings / nulls → `—` via `reportText`, so a blank cell is never read as
145	  an empty answer
146	- booleans → `Yes` / `No` via `yesNo`
147	- the STEM Fest `payment` column → `Verified` / `Pending`
148
