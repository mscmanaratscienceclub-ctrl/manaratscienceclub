## Environment workaround
The WSL2 session uses Windows node (nvm4w `node.exe`). drizzle-kit's esbuild
spawn fails on the 9p-mounted `/mnt/e/...` paths with `EBUSY` when invoked
from a WSL shell. Running the same command from `cmd.exe` works:

```
cmd.exe /c "cd /d E:\Web Dev\test\manaratscienceclub && node node_modules\drizzle-kit\bin.cjs generate"
```

`pnpm db:generate` should still be the documented command — the WSL/cmd
discrepancy is a local dev-env quirk, not a project change.
