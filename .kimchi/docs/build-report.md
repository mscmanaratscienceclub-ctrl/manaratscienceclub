## Migration SQL summary

The generated `drizzle/0004_powerful_albert_cleary.sql` contains a single statement:

```sql
DROP TABLE "applications" CASCADE;
```

This drops the `applications` table along with all its dependent objects (the `applications_user_id_user_id_fk` foreign key to `public.user`, the `applications_user_id_unique` constraint, the `users manage own applications` RLS policy, and the table-level RLS enablement). The `CASCADE` form is functionally equivalent to the plan's required `DROP POLICY` + `DROP TABLE` sequence — the RLS policy is removed as a dependency of the table.

Critically, the migration does **not** touch the `posts.custom_author_name`, `posts.custom_author_avatar`, or `posts.custom_author_bio` columns that were added in `0003_cooing_sentinels.sql`. The CMS is intact.
